# M7 threat model and review notes

Task T7.6a of the [M7 plan](../plans/m7.md). This is the input to the human sign-off T7.6b: it lists what M7 exposes, who could attack it, what stops them (with the code and the test that proves it), and what is accepted or still open. Written against commit `efece8b` plus the uncommitted hardening of the same day (timeouts, SHA pins, RBAC, `.dockerignore`), 2026-10-04. Line numbers are as of that tree.

**Rule of this document.** A mitigation is listed only with a code link (`path:line`) and, where one exists, the test that exercises it. A row marked "code only" has no dedicated test; the open items list the ones to close before exposure (CI and deploy rows are checked only by running them on the target).

## Deployment assumed

From [product decision 0001](../decisions/0001-m7-hosting-accounts-and-sharing.md) and the owner's decisions:

- **Self-host first, one user.** One instance, one bearer token, no accounts, SQLite (Decision 1). A hosted service is later and out of scope.
- **Private network.** The static app (Caddy image) and the sync server run behind a reverse proxy that ends TLS, reachable on a private network only. The server listens on `127.0.0.1` by default (`apps/server/src/config.ts:143`) and its README says not to expose it to the internet.
- **Shares** default to 30 days or never, 50 MB, 100 active shares; the self-hoster is responsible for what the instance hosts (Decision 4).
- **Scripts** from other people's documents do not run until the user allows them per document; auto-run stays locked off until T7.6b is signed (Decision 2, `apps/web/src/scripts/policy.ts:29`).

## Assets

| Asset                          | Where it lives                                                                   | Why it matters                                                                 |
| ------------------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Documents (the user's models)  | Browser OPFS or IndexedDB; the server's SQLite (log, snapshots, versions)        | The user's work; confidentiality and integrity                                 |
| The bearer token               | Server env or file; each browser's `localStorage` (`manufakture.server`)         | Full read and write of every synced document and share on the instance         |
| The per-client key             | Generated per synced document, stored with its sync state in the browser library | Lets one browser copy submit as its `clientId`; the server keeps only its hash |
| Share bundles (`.mfkview`)     | The server's `shares` table                                                      | Public to whoever holds a link; may include `source.mfk`                       |
| Blobs                          | The server's `blobs` table, by SHA-256                                           | Imported file bytes                                                            |
| The user's machine and browser | The page, its workers, storage quota, CPU                                        | Scripts and imported files run or parse there                                  |
| Server availability            | One Node process on the event loop                                               | One user's sync; a stall blocks every device                                   |
| The deploy pipeline            | GitHub Actions, GHCR, the cluster                                                | Whoever controls it serves the app to the user                                 |

## Actors

| Actor                          | Can                                                                                          | Cannot (by design)                                                                |
| ------------------------------ | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **Self-hoster** (the user)     | Everything: holds the token, runs the server and the static site                             | Trusted. Mistakes (exposing the server, weak proxy config) are in scope           |
| **Holder of a share link**     | `GET /api/shares/:id` for that id                                                            | List shares, guess other ids, reach any other route                               |
| **Hostile server**             | Send any bytes in answer to the app (a server URL the user typed, or a compromised instance) | Make the app hold an invalid document, run scripts, or read other origins' data   |
| **Hostile document author**    | Craft a `.mfk`, `.mfkview` or synced document, including scripts, names and drawings         | Run a script before the user allows it; reach the network, storage or DOM from it |
| **Other origins (web pages)**  | Make the user's browser send requests to the server or load the app in a frame               | Read responses without CORS, send the token (no cookies), frame the app           |
| **Network attacker**           | Observe or alter traffic on the private network                                              | Read or alter HTTPS traffic (TLS at the proxy); HSTS pins the app to HTTPS        |
| **Malicious contributor/fork** | Open pull requests, push branches if given write access                                      | Reach the publish token or a self-hosted runner without review (see section 8)    |

## Entry points

| Entry point                                                          | Auth                         | Trust boundary crossed                                |
| -------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------- |

| `GET /api/documents/:id/socket` (WebSocket)                          | Token as subprotocol, Origin | Network to server; pushes from server to every device |
| `GET /api/shares/:id`                                                | None (public)                | Internet-facing read of stored bytes                  |

| The static app and viewer (`index.html`, `viewer.html`, `sw.js`)     | None                         | Host to browser; CSP and headers                      |
| Scripts (`packages/script` in the regen worker via `packages/regen`) | Per-document opt-in          | Document author to the user's machine                 |
| `.mfk` and `.mfkview` imports, `#src=` viewer links, viewer handoff  | None                         | File or URL author to the page                        |
| The service worker                                                   | Same origin                  | Cache to page, across builds                          |
| CI (`.github/workflows/ci.yml`) and deploy (`deploy.yml`, `deploy/`) | GitHub permissions           | Repository to registry and cluster                    |

### 5. Scripts (T7.2b, T7.2c, T7.2e)

A script is untrusted code from the document's author. Defences in depth: it does not run until allowed; it runs in QuickJS (WebAssembly) with only `ctx`; every value crossing is re-validated by the host; soft limits stop it; the 10 s watchdog terminates the worker; and the worker's CSP forbids any network but the app's own origin.
